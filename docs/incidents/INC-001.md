# INC-001 — External Service Outage

## 1. Загальна інформація

Incident ID: INC-001

Дата: 2026-11-28

Компонент: external_service.py

Зовнішня залежність: http://127.0.0.1:5001/external/status

Тип інциденту: недоступність зовнішньої залежності.

Середовище: локальне тестове середовище QualityLab_1.

## 2. Severity

Severity: SEV-3.

Обґрунтування:

Основний Flask API залишався доступним та повертав HTTP 200.

Повної відмови системи не відбулося.

Однак функціональність, що залежить від external_service.py, перейшла у degraded mode, а latency перевищила цільове значення.

## 3. Час виявлення

Incident start:

2026-11-28 10:02:27 UTC

Спосіб виявлення:

контрольований SRE-тест недоступності зовнішньої залежності та аналіз відповіді endpoint /tasks/summary.

## 4. Симптом

Зовнішній сервіс на TCP-порту 5001 був недоступний.

HTTP-запити завершувалися помилкою:

Connection refused.

Компонент external_service.py виконав три повторні спроби та після цього активував fallback.

## 6. Виконані дії

Під час інциденту виконано:

1. Перевірено відсутність процесу на TCP-порту 5001.
2. Підтверджено недоступність зовнішньої залежності.
3. Виконано п'ять контрольних запитів до /tasks/summary.
4. Зафіксовано retry-поведінку.
5. Зафіксовано fallback response.
6. Зафіксовано latency кожного запиту.
7. Результати збережено у lab12_results/incident_fail.log.

## 7. Тимчасовий обхід

Тимчасовим механізмом стабілізації є вбудований fallback у external_service.py.

Після трьох невдалих спроб компонент повертає:

status = degraded

source = fallback

attempts = 3

degraded = true

Завдяки цьому endpoint /tasks/summary продовжує відповідати HTTP 200.

## 10. Вплив на SLA/SLO

### Availability

Усі п'ять запитів повернули HTTP 200.

Тому під час контрольного тесту порушення availability через повну недоступність API не зафіксовано.

### Latency

Цільовий latency threshold у docs/slo.yaml:

p95 < 300 ms.

Зафіксовані значення:

619.53 ms

622.22 ms

616.17 ms

618.36 ms

621.50 ms

Середнє значення:

619.56 ms.

Усі п'ять запитів перевищили 300 ms.

Отже, у контрольному вікні зафіксовано порушення latency objective.

Оскільки інцидент є коротким контрольованим тестом, він сам по собі не доводить порушення повного 30-денного SLA-вікна, але показує подію, яка витрачає Error Budget.

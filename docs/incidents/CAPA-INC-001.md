# CAPA Plan — INC-001

Incident: INC-001

Component: external_service.py

## 1. Короткий контекст

Під час інциденту INC-001 зовнішній сервіс на порту 5001 був недоступний.

Основний API продовжував працювати, але endpoint `/tasks/summary` переходив у degraded mode.

Для кожного запиту система виконувала три повторні спроби, після чого використовувала fallback.

У результаті всі 5 контрольних запитів залишилися доступними через HTTP 200, але їх latency становила приблизно 616–622 ms, що більше цільового значення 300 ms.

---

# CAPA-01 — Corrective Action

Тип: Corrective

## Опис

Додати окрему перевірку доступності зовнішнього сервісу на порту 5001.

Перевірка повинна дозволяти швидко визначити, чи працює зовнішня залежність, не чекаючи виконання основного користувацького запиту до `/tasks/summary`.

## Що саме вона виправляє

Під час INC-001 проблема була виявлена тільки тоді, коли система спробувала звернутися до зовнішнього сервісу.

Окрема перевірка дозволить раніше визначати його недоступність і швидше починати відновлення.

## Effectiveness Check

# CAPA-02 — Corrective Action

Тип: Corrective

## Опис

Переглянути retry-механізм у `external_service.py`, щоб система швидше переходила до fallback, коли зовнішній сервіс недоступний.

Поточна реалізація виконує три спроби з паузами між ними.

## Що саме вона виправляє

Під час INC-001 усі запити виконували три спроби.

Через це latency становила приблизно 620 ms, хоча цільове значення для системи — менше 300 ms.

Оптимізація retry-поведінки повинна зменшити час очікування користувача при недоступній зовнішній залежності.

Owner:

SRE Owner

Deadline:

2026-12-05

Status:

Planned

## Effectiveness Check

1. Вимкнути зовнішній сервіс на порту 5001.
2. Виконати щонайменше 5 запитів до `/tasks/summary`.
3. Зафіксувати latency кожного запиту.
4. Порівняти результат із INC-001.
5. Перевірити, що fallback продовжує працювати і API не повертає HTTP 5xx.

Дія вважається ефективною, якщо система продовжує коректно переходити у degraded mode, але середній час відповіді стає меншим порівняно з INC-001.

# CAPA-03 — Preventive Action

Тип: Preventive

## Опис

Додати моніторинг зовнішньої залежності та alert, який повідомляє про недоступність сервісу на порту 5001.

Перевірка повинна виконуватися незалежно від користувацьких запитів.

## Який потенційний збій вона запобігає

Ця дія зменшує ризик того, що зовнішній сервіс буде недоступний тривалий час, а команда дізнається про це тільки після появи degraded responses у користувачів.

Моніторинг дозволить раніше виявити проблему і почати відновлення.

## Effectiveness Check

# 5. Зв'язок CAPA з RCA

INC-001 показав, що система має retry та fallback, тому повного падіння API не сталося.

Водночас було виявлено дві проблеми:

- недоступність зовнішнього сервісу не контролювалася окремо;
- retry збільшував latency запиту.

CAPA-01 та CAPA-02 спрямовані на виправлення проблем, які проявилися під час INC-001.

CAPA-03 є попереджувальною дією і повинна зменшити ризик пізнього виявлення аналогічних проблем у майбутньому.

# CCB-001 — Протокол Change Control Board

## 1. Загальна інформація

RFC-ID: RFC-001

Дата засідання: 2026-11-28

Тема: Перехід QualityLab_1 від in-memory storage до SQLite.

## 2. Склад CCB

У засіданні беруть участь такі ролі:

System Architect — оцінює архітектурну цілісність зміни.

QA Lead — оцінює ризик регресії та необхідний набір тестів.

SRE Representative — оцінює вплив на експлуатацію, backup, recovery та monitoring.

Product Owner — оцінює цінність зміни та терміни реалізації.

Кворум: наявний.

## 3. Розглянуті аргументи

Архітектурний аргумент:

SQLite усуває основне обмеження поточного in-memory storage — втрату runtime-даних після перезапуску застосунку.

QA аргумент:

Зміна persistence layer створює ризик регресії, тому необхідні повні regression tests та окремий restart persistence test.

SRE аргумент:

Persistent storage покращує можливість резервного копіювання та відновлення системи, але потребує backup policy та rollback procedure.

Product аргумент:

Зміна підвищує надійність системи та готує її до подальшого production deployment.

## 4. Рішення CCB

Рішення:

APPROVED WITH CONDITIONS.

RFC-001 погоджено за таких умов:

- усі regression tests повинні бути зеленими;
- перед міграцією необхідно створити backup;
- migration procedure повинна бути перевірена;
- rollback plan повинен бути готовий;
- документація повинна бути оновлена;
- CHANGELOG повинен містити запис про зміну;
- health check після deployment повинен повернути HTTP 200;
- OpenAPI contract не повинен отримати breaking changes без migration guide.

## 5. Термін виконання

Зміна може бути реалізована у погоджене deployment window:

18:00–19:00 у день без активних демонстрацій системи.

## 6. Регламент CCB

Планові засідання CCB проводяться перед реалізацією Normal Change із середнім або високим рівнем ризику.

Emergency Change може бути розглянута позачергово.

RFC повинна бути подана до CCB разом із:

- описом зміни;
- Impact Analysis;
- Risk Exposure;
- rollback plan;
- test plan;
- deployment window.

## 7. Change Freeze

Якщо Error Budget із docs/slo.yaml вичерпано, вводиться change freeze.

Під час change freeze:

- нові функціональні релізи заборонені;
- дозволені лише reliability fixes;
- дозволені security fixes;
- дозволені зміни для усунення активного інциденту.

Звичайні релізи відновлюються після повернення reliability metrics у межі SLO та окремого рішення CCB.
